6. Build Your Own Project & Find Ideas
Students are not limited to the provided project list and can propose an original idea. The project should solve a clear problem for a specific user, provide meaningful functionality, use an appropriate tech stack, include frontend/backend and data storage where required, and be properly tested and deployed.
For inspiration, students can explore:
GitHub – Open-source projects and ideas
OpenAI Codex – Brainstorming and implementation planning
Google Antigravity – AI-assisted development
Devpost – Hackathon projects and problem statements
Kaggle – Datasets and AI/ML ideas
Google Codelabs – Hands-on project examples
Developer communities, blogs, and open-source repositories
Use these resources for inspiration only. Do not copy an existing project and submit it as your own. Ensure your idea meets the program requirements before starting.

9. GitHub Repository Requirements
Each student should maintain a GitHub repository for their project.
The repository should contain:
project/
│
├── frontend/
├── backend/
├── README.md
└── .gitignore

The repository should not contain:
Database passwords
API keys
Secret keys
.env files
Authentication secrets
Private credentials
Use environment variables instead.

10. README Requirements
Your README.md must include the following sections:
1. Project Name
Provide the name of your project.
2. Problem Statement
Briefly explain the problem your application solves and why the project is useful.
3. Features
List the major core and bonus features implemented in the project.
4. Technology Stack
Mention the technologies, frameworks, libraries, databases, APIs, and AI services used.
5. Screenshots
Add screenshots of the major application screens and important features.
6. Live Demo
Provide the deployed Vercel URL of the application.
7. Backend
If applicable, provide the deployed backend/API URL.
8. Setup Instructions
Explain the steps required for another developer to run the project locally, including installation and configuration.
9. Environment Variables
List the required environment variable names without exposing their actual values.
Important: Never commit API keys, passwords, OAuth secrets, access tokens, or other sensitive credentials to GitHub.

11. Avoid These Common Mistakes
Do not submit:
A project that only contains a static UI
A copied GitHub project with no meaningful changes
A tutorial project submitted without understanding it
An application with broken API calls
An application with no working database when a database is required
An application containing exposed API keys
A project that only works on your local machine
A project that you cannot explain





12. Project Completion Certificate
The Project Completion Certificate is awarded based on successful completion and submission of the project requirements.
To be eligible, students must:
Select or propose a project
Build the project themselves
Use AI tools responsibly where applicable
Implement meaningful functionality
Test the application
Deploy the application
Submit the GitHub repository
Submit the live application URL
Submit the required documentation
Be able to explain the project and its implementation
⚠️ IMPORTANT CERTIFICATE NOTE
The Project Completion Certificate will be provided only to students who successfully build and submit their own project.
Using AI coding tools is allowed and encouraged, but submitting copied work, another student's project, or an unchanged existing project does not qualify as completing the project.
The purpose of this project is to demonstrate that you can take an idea, use modern development tools, build a working application, debug it, deploy it, and understand what you have built.
